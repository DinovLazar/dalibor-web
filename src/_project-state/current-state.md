**Last updated:** 2026-09-04 — **Part 3 · Phase 3.01 (Code) — mobile experience overhaul.** Everything below `sm` (640px) was rebuilt: structure, density, touch and payload. Headlines at 375×812: **Reviews 12,118 → 3,828px (−68%)**, **Home 4,181 → 3,447px (−18%)**, one review card **522 → ~190px**, the topic filter **312 → 44px** (now a snap-scrolling rail), the search box from y=615 to y=272, **zero** sub-44 interactive targets across all 162 mobile measurements (was 300+), **zero** horizontal overflow, and the preloaded font payload **244,436 → 118,648 bytes per page (−51.5%)** with `@font-face` rules 68 → 24. New foundation in `globals.css` (`--page-gutter`, `full-bleed`, `.band-cream`/`.band-parchment` + `--band-card`, `.card-surface`/`.card-flat`, a phone type scale by token override, `.tap-target`, `.chip-rail`, `.to-top`, `.list-cap`, `page-gutter`/`safe-top`/`safe-bottom`). Viewport plumbing added: `theme-color`, `viewport-fit=cover`, `manifest.webmanifest`. **A latent `tailwind-merge` defect was found and fixed** — it classified every custom `text-*` size token as a colour and dropped it whenever a colour followed in the same `cn()` call, so `cn("text-h4 text-text")` returned `"text-text"`; that had been silently disabling parts of the Style A type scale and would have disabled the whole new phone scale. Fixing it is the one intentional desktop change (see Known issues). Full detail: `Part-3-Phase-01-Completion.md`.
